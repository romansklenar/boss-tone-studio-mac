# 1.0.1 Hardening Implementation Plan

Status: executed on 2026-10-30 on `fix/hardening-1.0.1`, to be released as 1.0.1 by a release pull request of its own.
This file records how the work was split and what changed on the way; the code,
[ADR-0014](../decisions/ADR-0014-events-in-batches.md) to
[ADR-0017](../decisions/ADR-0017-quitting-waits-with-terminate-later.md) and
[`doc/bridge-protocol.md`](../bridge-protocol.md) are the reference. Spec: the
[design](../design/2026-10-30-hardening-1-0-1.md).

**Goal:** MIDI calls without a lock, events fetched in batches, quitting that waits at logout, page-chosen files read
and written through checked descriptors — with nothing the page or the amp sees changed.

## How it ran

Four tasks, each implemented and then reviewed on its own, in this order, since the later ones touch the same files
(`Bridge.swift`, `doc/bridge-protocol.md`) in other places. Every task ran `make check` before its commit, and
`doc/bridge-protocol.md` changed with the code it describes. Then a review of the whole branch with one round of fixes,
an amp test of the built `.app`, local code reviews with a second round of fixes, and a documentation audit.

## Tasks

What each task delivered, and what its review changed:

1. **MIDI controller on a serial queue** (ADR-0015) — the controller's connects, disconnects and sends run on a
   serial queue with no lock held while the backend is called; a fake backend that reports a setup change from inside
   its calls pins it. Its review noted that the CoreMIDI backend's header no longer matched the contract and that the
   test could not show the handler ran; both were fixed in the later rounds.
2. **Events in batches** (ADR-0014) — the command `$$app_getevents` and the injected script's local queue behind
   `$$app.getevent`. Roland's `native.js` ran against the script in Node with a stub XHR: an idle poll cost one request,
   three events two, dispatched in order. Its review noted, and ADR-0014 now says, that events left in the script's
   queue are lost if the page reloads before the next poll.
3. **Page-chosen files through checked descriptors** (ADR-0016) — `O_NOFOLLOW`, `F_GETPATH` checked against the same
   rule, and writes through a temporary file created and renamed in the checked folder's descriptor; tests swap a link
   in after the check, for the file and for a folder above it.
4. **Quitting waits instead of cancelling** (ADR-0017) — `.terminateLater`, and the reply once the window has closed.
   The executable has no unit tests, so this was left to the amp test.

The whole-branch review found that a save reset the file's mode and that reading a FIFO blocked in `open`. Its fixes:
saves keep the replaced file's permission bits, a FIFO reads as no file without waiting for a writer, the temporary
file gets a fixed-length name so the longest names still save, and the path checks became internal to `FileAccess`.

The local reviews then found a socket or device that refuses to open reading as an error instead of no file, a read
that could see `EAGAIN` after opening with `O_NONBLOCK`, setuid, setgid and sticky bits carried over a save, and a
picked file refused when `F_GETPATH` named another of its hard links. Their fixes: such files read as no file again,
reads run in blocking mode, only the permission bits are copied, and a same-file check (device and inode, the checked
path looked up without following any link) backs up `F_GETPATH`. They also answered an empty event poll without a JSON
encoder and handed out a fetched batch by index instead of shifting it.

## Checks

- `make check` before every commit; 258 tests at the end. Unit tests never create a CoreMIDI client or a window.
- Amp test of the built `.app` with a KATANA-HEAD MkII on a copy of the data folder, with `BTS_TRACE=1`: edits and a
  Librarian transfer; a `.tsl` with a non-ASCII name saved and opened again; Cmd-Q, the close button, and
  `osascript -e 'quit app "…"'` each ended through the handshake with exit code 0; with the page's process stopped, the
  AppleScript quit ended through the 2 s fallback.
