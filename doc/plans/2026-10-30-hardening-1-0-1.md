# 1.0.1 Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** MIDI calls without a lock, events fetched in batches, quitting that waits at logout, page-chosen files read
and written through checked descriptors — with nothing the page or the amp sees changed.

**Architecture:** `MidiController` serialises backend calls on its own `DispatchQueue` and keeps a short lock for
state only; the bridge gains `$$app_getevents` and the injected script serves `$$app.getevent` from a local queue;
`AppDelegate` answers `.terminateLater` and replies when the window closes; `FileAccess` owns check-and-use through
descriptors.

**Tech Stack:** Swift 6, SwiftPM, Swift Testing, Foundation/Darwin/AppKit; no dependencies.

**Spec:** `doc/design/2026-10-30-hardening-1-0-1.md` (and ADR-0014).

## Global Constraints

- Read `AGENTS.md` and `REVIEW.md` first; they bind every task. `doc/bridge-protocol.md` is the spec for `Sources/` and
  changes in the same task as the code it describes.
- No change to MIDI bytes or their order, event texts, HTTP statuses or bodies, or `[bts]`/`[trace]`/`[js]` lines
  (except that `$$app_getevents`, like `$$app_getevent`, prints no trace line).
- `make check` (sandbox off) before every commit; build only into the repo's `.build`; Conventional Commits with a
  scope and the trailer `Co-authored-by: Claude <noreply@anthropic.com>`; never amend; no `VERSION`/`CHANGELOG.md` edits.
- The private hygiene grep over `git log -p origin/main..HEAD` prints 0 before any push. No personal names in tests.
- Unit tests never create a CoreMIDI client and never show a window.

## Review Focus

1. A backend that reports a setup change from inside `connect`/`send` (CoreMIDI may) must not deadlock — Task 1 test.
2. Two pages or a reload polling at once must not lose or duplicate events — Task 2 test (two `app_getevents` calls).
3. A save to a path whose parent folder does not exist yet inside the data folder still works — Task 3 test.
4. A failed write leaves no temporary file behind and the old file intact — Task 3 test.
5. Quitting when the page never answers still ends after the fallback, at logout too — Task 4 manual check.

**Interfaces:**
- Produces (on `FileAccess`):

    throws the refusal `MessageError("\(path) was not chosen in a file dialog")`, `StorageError.notUTF8`, or a

    writes atomically; throws `MessageError("\(path) was not chosen in a save dialog")` when refused.

    `func writeChecked(_ text: String, to file: URL, asked path: String) throws` (internal): the open-and-verify half,
    given the canonical URL from `checkRead`/`checkWrite`, so a test can swap a link in between.

- [ ] **Step 2: Run them** — Expected: FAIL (methods missing).

- [ ] **Step 3: Implement**

Reading: `open(canonical, O_RDONLY | O_NOFOLLOW | O_CLOEXEC)`; `ENOENT`/`ENOTDIR` → nil; `ELOOP` → the refusal;
`fstat` not `S_IFREG` → nil; `fcntl(fd, F_GETPATH, buffer)` (buffer `MAXPATHLEN`) and the result must pass the read
rule (app folders, opened or saved picks) or it is the refusal; read to the end, then the UTF-8 check that
`readTextOrThrow` does. Writing: `open(parent, O_RDONLY | O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC)`, `F_GETPATH` on it plus
`"/" + name` must pass the write rule (app folders or saved picks); `openat(dirfd, ".<name>.<random>.tmp",
O_WRONLY | O_CREAT | O_EXCL | O_NOFOLLOW | O_CLOEXEC, 0o644)`; write all bytes; `close`; `renameat(dirfd, tmp, dirfd,
name)`; on any failure `unlinkat` the temporary file. Share the rule with `checkRead`/`checkWrite` (one private
predicate per set), never a second copy. The descriptors close on every path (`defer`).

### Task 4: Quitting waits instead of cancelling

**Files:**

**Interfaces:**
- Consumes: `Bridge.windowShouldClose() -> Bool` (true once the window may go), the window closing after the
  handshake (`WebWindow.closeWindow()`), unchanged.

- [ ] **Step 1: Implement**

`applicationShouldTerminate`: `bridge.windowShouldClose()` true → `.terminateNow`; otherwise remember that a reply is
owed and answer `.terminateLater`. Observe the window closing (`NSWindow.willCloseNotification` for the app's window,
or a callback from `WebWindow`); when a reply is owed, clear it and call `NSApp.reply(toApplicationShouldTerminate:
true)`. A second terminate request while a reply is owed answers `.terminateLater` again without starting a second
handshake (`windowShouldClose` already handles the repeat). No unit test (the executable target has none); keep the
logic small enough to read at a glance.

- [ ] **Step 2: Run `make check`** — Expected: pass.
