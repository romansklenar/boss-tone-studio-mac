# Hardening for 1.0.1: MIDI without a lock, events in batches, quitting at logout, files through descriptors

Status: approved, 2026-10-30. The follow-ups from the 1.0.0 reviews that need an amp test; they ship together in one
pull request, released as 1.0.1 by a release pull request of its own.

## Why

Nothing is broken for the user today, so none of this may change what the page or the amp sees. Each item closes a
weakness the reviews of 1.0.0 named:

1. `MidiController` holds an `OSAllocatedUnfairLock` across CoreMIDI calls, which REVIEW.md flags, and every queued
   event costs the page one synchronous request.
2. Quitting answers `.terminateCancel` while the page takes the amp out of editor mode, so a logout, restart or shutdown
   is cancelled ("BOSS TONE STUDIO cancelled logout") instead of waiting for the app.
3. `fs_readString` and `fs_writeString` check a path and then open it by name again, so a link swapped in between is
   followed.

## Goals

- **MIDI:** the controller's connects, disconnects and sends run one at a time on a serial queue of its own; no lock is
  held while CoreMIDI is called. The lock that remains guards plain state only.
- **Events:** the injected script fetches every queued event in one request and hands them to `native.js` one by one;
  `native.js` and its 50 ms polling stay as they are.
- **Quitting:** `applicationShouldTerminate` answers `.terminateLater` while the page answers, and the app replies once
  the close handshake has ended (the page's `$$app_exit` or the fallback). Cmd-Q, Cmd-W and the close button behave as
  before.
- **Files:** a page-chosen path is opened as a descriptor without following a link in its last component, and the
  descriptor's own path (`F_GETPATH`) is checked against the read or write set before a byte is read or written. A
  write goes to a temporary file created next to the target through the folder's descriptor and renamed over it, so it
  stays atomic.

## Non-goals

- Pushed events (`app_startevent` with `evaluateJavaScript`): they would end the polling, but `--browser` mode has no
  window to push into and the page would then never poll. Batching keeps one transport for both modes.
- Declaring `.tsl` and `.alb` in `Info.plist`, token-for-cookie exchange, proxy CSP, request caps: other follow-ups.
- Storage (`storage.json`, `storage2/`): the app's own folder, written by keys the bridge names; it keeps its path API.

## Anti-goals

- Any change to MIDI bytes, their order, event texts, statuses, bodies or `[bts]`/`[trace]`/`[js]` lines, except the
  new command's trace line.
- A send that returns before CoreMIDI has it: `$$app_exit` must still go after the page's last send (editor mode off).
- Waiting forever at logout: the existing exit fallback (2 s) still ends the wait.

## Decisions (mine, as the user delegated them)

- **Serial queue, `sync`:** callers keep their synchronous answers (a failed connect is still reported before the
  command returns, a send still reaches CoreMIDI before `$$midi_send` answers). The CoreMIDI notification handler only
  compares port lists under the short lock and never waits for the queue.
- **New command `$$app_getevents`:** answers a JSON array of the queued events (possibly empty) and empties the queue.
  `$$app_getevent` stays for anything that calls it directly. The injected script defines `$$app.getevent` over a local
  queue: when that is empty it asks `$$app_getevents` once, so a poll costs one request when nothing happened and two
  when something did, however many events there were. ADR-0014 records it.
- **Termination:** the delegate keeps the pending reply and calls `NSApp.reply(toApplicationShouldTerminate: true)` when
  the window closes after the handshake. AppKit runs the run loop in modal panel mode meanwhile; the bridge's hops to
  the main thread use the main queue, which that mode serves. The amp test checks it.
- **Descriptors:** `open(path, O_NOFOLLOW | O_CLOEXEC)` for reads (a link in the last component fails with `ELOOP`);
  `F_GETPATH` on the descriptor, and the result must pass the same rule as before (app folders, or picked in a dialog).
  Writes: the parent folder opened with `O_DIRECTORY | O_NOFOLLOW`, its `F_GETPATH` plus the file name checked against
  the write set, a temporary file by `openat(…, O_CREAT | O_EXCL | O_NOFOLLOW)`, written and closed, then `renameat`.
  The answers stay as today: a missing file reads as `undefined`, a refused path throws the same text.

## Left to the builder

File layout, names and the exact split of tests, within REVIEW.md; `doc/bridge-protocol.md` and the comments updated in
the same pull request.

## How it is checked

- Unit tests (Swift Testing): the controller never calls the backend while its lock is held (a fake backend that probes
  the lock), and calls stay in order; `$$app_getevents` order and emptiness; the injected script's local queue in the
  `jssim` check against Roland's `native.js`; a link swapped into a checked path is refused for reading and writing; a
  write is still atomic.
- In the window with the amp: edits and Librarian transfers as before, a `.tsl` opened and saved, Cmd-Q with editor mode
  off, and `osascript -e 'quit app "BOSS TONE STUDIO for KATANA MkII (Apple Silicon)"'` quits after the handshake
  instead of being cancelled.
